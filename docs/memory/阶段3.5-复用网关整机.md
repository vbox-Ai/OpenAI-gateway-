# 阶段 3.5 记忆点：复用网关整机路线（iOS 静态库验证）

## 决策
移动端主线从「FFI 嵌 29 家插件」转向「移植 agent2api-server 整机」。

## 关键发现
- 网关（aimod-cc/Agent2API）的 `desktop-tauri/src-tauri/server/` 是**独立 headless HTTP 服务器**
  （`agent2api-server` bin），与 Tauri 桌面壳分离。
- 它已包含：18 家内置 provider（编译在里，免子进程）+ 完整 /api/* 与 /v1/* + 完整 UI
  （自己 serve ui/ 目录 + 注入 web_shim 桥）+ SQLite（bundled）+ rustls（纯 Rust）。
- 依赖全纯 Rust：axum + rustls + rusqlite bundled，理论 iOS 兼容。

## 验证结果
- `cargo check --target aarch64-apple-ios -p agent2api-server` → **success**
- `cargo build --release --target aarch64-apple-ios --lib` → **success**，产出
  `libagent2api_server.a`（**50.25 MB**，含 18 家 provider + axum + rustls + SQLite）

## 代码改动
- `server/Cargo.toml` `[lib]` 加 `crate-type = ["staticlib", "rlib"]`
- `server/src/lib.rs` 加 FFI 探活 `agent2api_server_ping() -> 42`
- `.github/workflows/ios-check.yml` 新增（check + build --lib + 上传 .a）

## 下一步（阶段 3.6）
1. 把 `src/bin/agent2api-server.rs` 的 main() 时序（bootstrap / set_ui_dir / start / block_on）
   抽成库函数 `run_headless(data_dir, host, port, ui_dir)` + FFI 包装
2. Flutter 进程内启动该 server，webview 加载 `http://127.0.0.1:3065`（web_shim 形态 UI 零改）
3. 真机验证：18 家 provider 登录 + 签到 + OpenAI 兼容 API

## 与旧路线的关系
FFI 嵌 29 家插件的工作（OpenAI- 仓库）没白做：验证了 rustls/sqlite 能编 iOS、摸清了 FFI 路。
但作为主线，整机移植复用度远高于重造 host/UI。
