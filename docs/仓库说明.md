# Agent2API 自建仓库说明

> 本文档记录本项目（vbox-Ai 名下）各仓库的用途、对应关系、版本对齐与 iOS 移植架构。
> 最后更新：v3.3.0-beta.5.1 基线对齐完成后。

## 一、仓库全景

源项目是「一套网关 + 两套插件」三仓库结构。我们 fork 到 `vbox-Ai` 名下，一一对应：

| 我们的仓库 | 源仓库 | 作用 | iOS 移植角色 |
|---|---|---|---|
| `vbox-Ai/OpenAI-gateway-` | `aimod-cc/Agent2API` | **网关本体**（主仓库） | 核心：ipa 从这个仓库出 |
| `vbox-Ai/OpenAI-` | `ProvidersPlugin/Agent2Providers` | **原生插件**（provider 外挂） | 插件家的源码来源 |
| `vbox-Ai/OpenAI-web-` | `ProvidersPlugin/Agent2WebProviders` | **网页插件**（网页登录类 provider） | 网页插件家来源 |

## 二、各仓库做什么、有什么用

### 1. 网关 `OpenAI-gateway-`（核心）

Agent2API 的服务器本体。一个独立 Rust crate（`desktop-tauri/src-tauri/server/`），
服务两种形态：

- **Tauri 桌面端**：壳进程把 crate 当库链接，网关作为进程内 HTTP 服务器跑；
- **headless 服务器 / Docker**：`agent2api-server` 二进制自建 Tokio 运行时，托管管理界面。

职责：多提供商账号管理、模型目录聚合、会话式推理转发、网关 Key、代理池、
签到中心、AI 助手、定时任务、日志/报表、SQLite 存储、Web UI（`desktop-tauri/ui/`）。

**3.3.0-beta 线（当前基线）把 provider 分成了两块**：

- **内置 provider**（编译进网关本体，无需插件）：WorkBuddy / Accio / AutoClaw /
  Cline / Loomy / MonkeyCode / Qoder / ZCode / ModelScope + 自定义提供商；
- **插件 provider**（通过 `plugin_host` 模块拉起的独立子进程，stdio 通信）：
  小浣熊 / CatPaw / Trae / CodeArts / OfficeAce / OrcaTerm / KukuAI /
  Command Code / Antigravity 等 —— 源码在 `OpenAI-`（原生插件）与
  `OpenAI-web-`（网页插件）。

### 2. 原生插件 `OpenAI-`

29 家 provider 插件的 Rust 源码（含协议 crate `agent2api-provider-protocol`）。
网关通过 Git tag 引用协议 crate：

```toml
agent2api-provider-protocol = { git = "https://github.com/ProvidersPlugin/Agent2Providers", tag = "v3.3.0-beta.5.1" }
```

产出各平台的可执行插件二进制（Windows/macOS/Linux），桌面端网关靠它们把
插件家 provider 跑起来。

### 3. 网页插件 `OpenAI-web-`

承载「网页登录」形态的 provider 插件（智谱清言、DeepSeek 网页版等），
与原生插件共用协议，插件包独立分发。

## 三、版本对齐（当前：全部 v3.3.0-beta.5.1）

三仓库协议必须同版本，否则网关会报「官方插件低于网关版本」而停用插件。

| 仓库 | main 分支 | 版本 | 备份分支 |
|---|---|---|---|
| `OpenAI-gateway-` | `e0b5699` | 3.3.0-beta.5.1 | `legacy-3.0.8`（旧基线） |
| `OpenAI-` | `dcbc2c1` | 3.3.0-beta.5.1 | `legacy-0.2.1`、`legacy-ios-ffi` |
| `OpenAI-web-` | `857d4f4` | 3.3.0-beta.5.1 | — |

**踩过的坑**：早期误把源仓库 `main`（3.0.8，provider 内置旧架构）当「最新」，
导致手机端缺插件、缺新版设置页等 beta 线全部功能。源仓库的**最新开发在
`beta` 分支 / tag 上**，`main` 停在 3.0.8。现已统一对齐 beta.5.1。

## 四、iOS 移植架构

手机 ipa = **Flutter 壳（webview）+ 进程内 headless 网关**，不是重写原生 UI：

```
Flutter App
  └─ webview 加载 http://127.0.0.1:3065（复用网关 Web UI，零改）
  └─ dart:ffi 调 libagent2api_server.a（静态库链接进主二进制）
        └─ agent2api_server_start(Documents, 3065)
              └─ 进程内跑起 headless 网关（内置 provider + 完整 API + web_shim）
```

关键补丁（相对上游 beta.5.1 的改动）：

- `server/Cargo.toml`：加 `crate-type = ["staticlib", "rlib"]`（iOS 静态库）；
- `server/src/lib.rs`：追加 `run_headless` / `SHUTDOWN` 停机句柄 /
  `agent2api_server_start|stop|ping` 三个 FFI 入口；
- `mobile-app/`：Flutter 壳（webview + FFI 绑定 + SafeArea + 导出走原生落盘 +
  `window.open` 转系统浏览器）；
- `.github/workflows/ios-build.yml`：单一工作流，cargo 交叉编译 → 链接静态库
  （`-Wl,-force_load` + `-u` 防 dead-strip）→ xcodebuild → 裸 ipa → Releases；
- `docs/memory/`：各阶段记忆点。

## 五、插件在 iOS 上的适配（两条路线）

beta.5.1 的插件是 `tokio::process::Command` 拉起的**独立子进程**。普通 iOS
沙盒禁止 App spawn 子进程，但**越狱 / TrollStore 环境可以**（platformized 后
`posix_spawn` 可用）。两条路：

1. **越狱 spawn（推荐，改动小）**：把插件 crate 交叉编译成
   `aarch64-apple-ios` 可执行文件，随 ipa 分发、启动时拷到可写目录并
   ldid 签名，`plugin_host` 原样 spawn。贴近上游架构，但依赖越狱环境。
2. **进程内嵌入（通用，改动大）**：插件编成 staticlib 嵌进主二进制，
   改 `plugin_host` 走协议库的进程内形态（`EmbeddedGateway`）。非越狱机
   也能用，工程量大。

当前状态：**内置 9 家 + 自定义，手机上直接可用**；插件家待上述任一路线落地。

## 六、升级流程

源项目出新版 → 同步三个 fork 到新 tag → 重放 iOS 补丁（`lib.rs` FFI /
`Cargo.toml` / `mobile-app`）→ 触发 `iOS 构建与发布` 工作流 → 出新 ipa →
越狱机 ldid 覆盖安装（bundle id 不变，Documents 沙盒数据保留）。

手机端目前无 App 内自动更新，升级 = 重打包 + 重装；自动更新为可选增强。
